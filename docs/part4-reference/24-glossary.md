# Glossary

Terms, abbreviations, and Akamai-specific nomenclature used throughout this documentation. All definitions describe behaviour as observed in BMP SDK v4.0.4 on Android (Argos 5.26.0).

---

| Term | Definition |
|------|------------|
| **_abck** | First-party cookie set by Akamai's edge servers during the web-based bot detection flow. In the mobile BMP context it is largely irrelevant -- mobile sensors are carried in the `x-acf-sensor-data` header instead -- but the cookie may still appear in HTTP responses and should be stored by the cookie jar. Not to be confused with `ak_bmsc`. |
| **ak_bmsc** | Session cookie issued by Akamai after the first valid sensor is accepted. It acts as a lightweight session token: subsequent requests that include a valid `ak_bmsc` may receive lighter server-side validation. Must be forwarded on every request alongside `akavpau_vpc_api_retail`. See [Cookie & TLS](22-cookie-policy.md). |
| **akavpau_vpc_api_retail** | Domain-scoped persistence cookie tied to Akamai's API gateway configuration for the Argos retail API. It works in tandem with `ak_bmsc` to maintain session continuity. The suffix (`vpc_api_retail`) varies per protected property; the `akavpau_` prefix is constant across deployments. See [Cookie & TLS](22-cookie-policy.md). |
| **BMP** | Bot Manager Premier -- Akamai's highest-tier bot detection product. The mobile variant documented here embeds a native SDK (`libakamaibmp.so`) and a hidden WebView challenge inside Android and iOS applications, as distinct from the web-only variant that relies on browser JavaScript and the `_abck` cookie. See [System Overview](../part1-understanding/01-overview.md). |
| **buildN** | JNI-exported function in `libakamaibmp.so` that takes the plaintext sensor fields and the `CryptoContext`, performs AES-128-CBC encryption with HMAC-SHA256 integrity, and returns only the encrypted sensor portion. The Java SDK layer then appends additional `$`-delimited segments (PoW response, CCA token, device attestation) to form the fully assembled `x-acf-sensor-data` header value. Called by the Java SDK on every API request. See [Generator Internals](../part3-generator/14-generator-internals.md). |
| **CircleProgressBar / String Deobfuscation** | A deliberately misnamed Java class (`CircleProgressBar.java`) in the BMP SDK that has nothing to do with UI rendering. It implements the XOR-based string deobfuscation routine used to decode all obfuscated string constants across the SDK layer, including API endpoints, encryption parameters, and bridge method names. |
| **CryptoContext** | Internal state object created once per SDK session that holds the randomly generated AES-128 key (16 bytes) and HMAC-SHA256 key (32 bytes), their RSA-encrypted forms, and the RSA public key. Both keys remain stable for the lifetime of the session; only the IV changes per sensor. See [Encryption](20-encryption.md). |
| **CyberFend** | The original company and internal brand name for the technology inside `libakamaibmp.so`. Akamai acquired CyberFend and repackaged its mobile SDK under the BMP product line. The Java namespace `com.cyberfend.cyfsecurity` and native symbol prefixes still carry the CyberFend name. |
| **device_attestation** | Binary attestation blob appended after the `$$$` delimiter in the sensor header. It proves the request originates from a genuine Android device by including hardware-backed attestation data. Sensors without it score 70+ on Akamai's risk scale and are automatically blocked. See [Sensor Format](../part1-understanding/03-sensor-format.md). |
| **DeviceProfile** | A JSON structure capturing all static device telemetry needed to generate sensors without a physical device at runtime. Includes screen dimensions, OS version, installed fonts, WebView user agent, and the 18 values returned by the `SensorInterface` bridge methods. Created once via Frida capture. See [Device Profiles](../part3-generator/18-device-profiles.md). |
| **GF(2) CLMUL / counter_large** | The `counter_large` value in field -115 (sub-position 13) is computed via carry-less multiplication (CLMUL) in GF(2^64). The algorithm multiplies the session interaction counter (`c5`) by a fixed constant `0x6DB60000DB6D`, reduced modulo the irreducible polynomial `x^64 + x^33 + x^1`. This is a pure deterministic function of `c5` alone --- it has no time dependency and no key. Originally misidentified as a "16-round Feistel cipher"; the true algorithm was determined by mathematical analysis of 47 captured `(c5, counter_large)` pairs, which revealed XOR-linearity consistent with GF(2) polynomial multiplication. Verified with 100% match rate against all real captures. |
| **JA3/JA4** | TLS client fingerprinting methods that hash the parameters of the ClientHello message (cipher suites, extensions, supported groups). Akamai uses these fingerprints at Tier 0 validation to verify the request's TLS handshake matches an expected mobile client profile such as `okhttp4_android_13`. See [Cookie & TLS](22-cookie-policy.md) and [Server Validation](../part1-understanding/06-server-validation.md). |
| **JSBridge / SensorInterface** | The `@JavascriptInterface`-annotated Java object injected into the hidden WebView as `window.SensorInterface`. It exposes 18 getter methods (e.g. `getDeviceModel`, `getScreenWidth`) that the challenge JS calls to collect device telemetry, plus `setSignal()` which receives the assembled plaintext signal back from JS. Implemented in `u7f.java`. |
| **MT19937** | The Mersenne Twister pseudo-random number generator, generated by the Java/native SDK layer for fields -172 and -170. Its output is embedded in these sensor fields as PRNG proof values; the server can mathematically verify that the values are valid outputs from a correctly-seeded Mersenne Twister. Incorrect MT19937 output triggers Tier 2 rejection. |
| **polymorphic JS** | Refers to the `sdk_challenge.js` file served by `/_sec/sdk_challenge.js`, which is regenerated on every request with randomised variable names, reordered code blocks, and fresh XOR keys for its string tables. The underlying logic -- a webpack-style bytecode VM -- remains functionally identical across serves, but the surface-level code never repeats. See [Challenge JS VM](../part1-understanding/04-challenge-js.md). |
| **pureJsSignal** | The subset of sensor data computed entirely within the challenge JS without relying on the `SensorInterface` bridge. It comprises three fingerprint algorithms (`ua_hash`, `pkgHashCode`, `uaHashCode`) whose names are deliberately misleading. See [pureJsSignal](../part1-understanding/05-purejs-signal.md) and [Algorithms](21-algorithms.md). |
| **r_token** | A per-session random token generated locally by the SDK in the format `r-{18_hex_chars}-{4_alphanum_chars}`, unique per session. It is embedded in field -100 and included in sensor submissions to identify the session. |
| **RooLink** | A third-party commercial sensor generation service (`github.com/roolinkio/roolink-go`) that the Go stock monitor previously used for BMP sensor generation. Replaced by the in-house sensor server (`src/sensor_server.py`). |
| **sensor_hash** | A compile-time constant (e.g. `s5-0.5-10252351`) baked into the Java SDK layer at Akamai's build time. Format: `s{format_version}-{sub_version}-{build_number}`. Not computed at runtime by native code --- confirmed via Ghidra analysis showing the string is absent from `libakamaibmp.so` and is passed from Java to `buildN` as part of the pre-assembled `-100` field. Must be recaptured once per SDK version update. See [Field Reference](19-field-reference.md). |
| **SensorSession** | The SDK-level session lifecycle that spans from the initial `/_bm/get_params` call through to session expiry. A single `SensorSession` maintains a stable `CryptoContext`, `r_token`, and `DeviceProfile`; multiple sensors are generated within one session, each with a fresh IV but the same encryption keys. |
| **serverSideSignal** | A session-specific challenge token issued by Akamai's edge during SDK initialisation. Passed to the challenge JS via the URL query string, included in the signal output, and validated server-side to bind the sensor to a specific session. |
| **sig** | MD5-based request signature for the Argos mobile API. Computed as `MD5(api_key + api_secret + unix_timestamp)`. Changes every second. Required as a query parameter on every API request; a stale `sig` is rejected with HTTP 401 or 403. See [API Client](../part3-generator/16-api-client.md). |
| **tls_client** | A Python or Go HTTP client library that allows precise control over TLS fingerprint parameters (cipher suites, extensions, ALPN, signature algorithms). Required for BMP integration because Akamai's Tier 0 validation rejects requests whose JA3/JA4 fingerprint does not match the expected `okhttp4_android_13` profile. See [API Client](../part3-generator/16-api-client.md). |
| **x-acf-sensor-data** | The HTTP header that carries the complete encrypted sensor payload on every API request to a BMP-protected endpoint. Its value follows the envelope format `6,a,{RSA_AES},{RSA_HMAC}${AES_CBC_PAYLOAD}${T1,T2,T3}$$${DEVICE_ATTESTATION}`. This header is the primary input to Akamai's server-side validation pipeline. See [Sensor Format](../part1-understanding/03-sensor-format.md). |
